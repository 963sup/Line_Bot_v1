# @line-work/repository

- Owns Repository identity/access/star, User-owned Repository Star Lists, authorized discovery projections, Label, Repository Milestone, Issue/IssueLabel, Discussion/comment and their lifecycle/command evidence.
- Issues, Discussions, Labels and Repository Milestones are distinct Repository-owned objects; Project Milestone is a different Project-owned concept.
- Repository scope, assignment qualification, lifecycle transition, expected version and request replay are validated by this owner.
- Events/history are durable evidence; retries are idempotent and corrections do not silently rewrite prior event meaning.
- HTTP, LINE and Assistant entrypoints use owner public contracts and do not mutate Repository relations directly.
- Owner login/repository name/issue number/milestone number are locators only. Protected reads and writes still resolve stable IDs and current access before exposing private data.
- Repository Star List is a User-owned curated grouping of that User's current Repository Stars. Create is private by default; publish is explicit; List membership never grants access; add requires current Star + current Repository access; Unstar removes matching List membership through the declared data invariant.\n- Discovery is a Repository-owned read projection, not an Explore Domain: current Trending ranks currently accessible Repositories by active Stars created in the last 7 days, then total Stars/name/id; current Activity projects immutable Issue events; published Star List discovery includes only active-owner public Lists with at least one viewer-visible Repository and never exposes hidden item counts.
- Current read APIs do not imply every GitHub-like write capability is active. Do not let Discussion, Label, Milestone or Project naming similarity move behavior out of the Repository owner or claim runtime completion without tests and topology/docs evidence.

- Runtime mutation authority follows activated capabilities, not table existence. Current writes are Repository create, Issue create/transition (including `next_issue_number` allocation), Repository star/unstar and Repository Star List create/update/publish/unpublish/membership/delete. Repository create is private-only, replay-safe, User-self or effective OrganizationOwner scoped; Organization creation bootstraps only the creator admin grant required for immediate access. General access grants, visibility/rename, Discussion/Comment, Label, Repository Milestone and IssueLabel management remain data-only/read-only until a real command consumer is activated.
