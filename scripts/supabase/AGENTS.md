# Supabase operation scripts

- `schema-source.mjs` reads ordered declarative SQL; `schema-local.mjs` rebuilds local desired state; `remote.mjs` compares/applies/verifies remote state; `postgres.mjs` owns SQL transport.
- Normal publication is `schema:remote sync`, only when `supabase/schemas/*.sql` changed. Apply the complete generated diff, including destructive DDL, in a transaction; do not precede it with historical compatibility or business-data conversions. A specifically governed one-time authority transition may join its reviewed cutover function to the introducing DDL transaction when old writers must remain frozen until the new constraints and authority marker exist; this is not a generic compatibility hook.
- Preserve exact project confirmation, non-pooling operator connection, TLS, timeout and advisory lock. Mutation requires validated current-main Release authorization.
- Require second diff = 0, ownership/security readback and unchanged migration-history fingerprint. No migration file/history creation, replay or repair; provider-owned auth/storage remain outside mutation scope.
- Scoped identifier authority cutover is detected from exact catalog objects and its durable marker. It locks governance and legacy writer tables in stable order, calls only the operator-owned cutover function at the exact Git revision, and persists a frozen marker plus count readback. The freeze remains in the database across process/job failures. Only the post-deployment `activate-identifiers` operator command may mark the runtime ready after exact-revision production readback. Missing, partial or malformed authority state fails closed; normal later schema sync never reruns the cutover.
- Before the first cutover on an existing application database, require machine-readable provider recovery evidence or the exact project/authority/schema risk authorization governed by [Recovery](../../docs/reference/operations/recovery.md). Persist minimal evidence before remote DDL, explicitly recording absent backup/recovery verification for the authorized unbacked path; never treat authorization as a verified backup. No generic skip flag. A catalog-proven fresh bootstrap has no retained business data and does not require that cutover recovery gate.
- Every remote database write, including foundation repair, performs a GitHub current-main readback immediately before issuing SQL. Plan/verify/recovery are explicit read-only diagnostics, never automatic work on unchanged schema. `activate-identifiers` is the sole unchanged-schema mutation and only resolves a pending frozen authority after deployment. Classification is diagnostic, not a DDL approval gate.
- Do not invent business metadata. Unknown results require readback before retry; rollback/unlock must preserve the original error.
- `.artifacts/supabase-remote/` is transient evidence, not a source of truth.

Test target, lock, transaction, history and acceptance behavior locally; remote convergence requires separate readback. Contracts: [Supabase](../../docs/reference/platform/supabase.md), [Release](../../docs/reference/operations/release.md).
