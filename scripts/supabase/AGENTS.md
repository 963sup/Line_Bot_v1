# Supabase operation scripts

- Scripts separate schema source/rebuild, local verification, remote reconciliation and remote mutation; a successful local check never proves remote convergence.
- `schema-source.mjs` owns reading ordered declarative SQL, `schema-local.mjs` owns local rebuild, `remote.mjs` owns `prepare|plan|sync|verify` reconciliation semantics, and `postgres.mjs` owns SQL execution helpers. Do not hide provider mutation behind a generic helper or workflow shell block.
- Remote operations require exact project identity, explicit target, preconditions, bounded transaction/timeout, least-privilege connection, post-write readback and reconciliation evidence.
- Preserve current schema authority in `supabase/schemas/`; migration history remains replay/recovery evidence and must not silently replace the current source.
- `repair` is the automatic Release's idempotent, metadata-free additive runtime-compatibility pass; it may only restore canonical current-compatible surfaces such as Account login and DailyCheckIn contracts from `supabase/schemas/`, with exact target checks and readback. `prepare` remains preserve-data expansion/preflight for schema changes and may require explicit business metadata. Neither may drop/rename legacy authority or authorize a manual contract. Automatic plain `sync` only applies plans classified `automatic`; unknown, destructive, data-sensitive or sensitive privilege transitions classify `manual` and fail closed. Schema-unchanged releases run `repair → verify`. Manual reconciliation is two-phase: `prepare-plan` produces `plan.sql` + `plan.sha256`; apply may pass `--allow-manual` only with `SUPABASE_REVIEWED_PLAN_SHA256` matching a freshly recomputed exact plan. Automatic Release never supplies owner business metadata. If exactly one legacy Enterprise lacks current `name` / `slug`, manual reconciliation may supply those two explicit values; `remote.mjs` binds them to the unique unresolved remote row under lock. Zero or multiple unresolved rows with supplied cutover input, or any conflicting persisted value, fail closed. All repository-owned remote mutations share the same PostgreSQL advisory lock; Production Web promotion remains blocked until same-revision database readback succeeds.
- Failure after an external write is an unknown result until independently read back; never retry with a new request identity without owner-specific idempotency and reconciliation.
- `.artifacts/supabase-remote/plan.sql`, `plan.sha256`, `verification.sql`, `migration-history.before.txt`, `migration-history.after.txt` and prepare JSON are transient operation evidence. Do not hand edit or commit them; if required evidence for the operation is missing, the run does not support a remote convergence claim.
- Changes to remote classification, target checks, artifact shape, prepare behavior or release assumptions need focused `scripts/supabase/*.test.mjs` coverage; update workflow/tooling contracts when their assumptions are affected.
